# 引擎接口说明书 — 象棋强软 v1.3.1

本文件是**引擎侧**的接口规范：本软件如何发现、识别、启动、驱动一个象棋引擎，以及你要如何把一个新引擎接进来。
软件自身的功能说明见同目录上一级的 `README.md`（两者并存，不合并）。

---

## 一、支持的协议与格式

本软件支持两种中国象棋引擎协议，**自动探测**，你不需要告诉它用哪种。

### 1.1 协议探测流程

```
本软件                                       引擎
  │  uci  ─────────────────────────────────▶ │
  │  ◀───────────  id name Pikafish ...      │
  │  ◀───────────  option name Threads ...   │
  │  ◀───────────  uciok                     │  ← 判定为 UCI 引擎
  │                                          │
  │  （若 3 秒内完全没有 uciok/ucciok）        │
  │  ucci ─────────────────────────────────▶ │
  │  ◀───────────  ucciok                    │  ← 判定为 UCCI 引擎
  │                                          │
  │  （两步都无响应 → 「无法识别为象棋引擎」） │
```

- 先发 `uci`；收到 `uciok` → **UCI 模式**；收到 `ucciok` → **UCCI 模式**。
- 若 `uci` 无响应，再发一次 `ucci`（兼容只认 `ucci` 的老引擎）。
- 探测超时默认为 3 秒；扫描引擎库时为 6 秒。

### 1.2 坐标约定（两种协议完全一致）

```
rank 9   a9  b9  c9  d9  e9  f9  g9  h9  i9     ← 黑方底线（将 e9）
rank 8   a8  b8  c8  d8  e8  f8  g8  h8  i8
rank 7   a7  b7  c7  d7  e7  f7  g7  h7  i7
rank 6   a6  b6  c6  d6  e6  f6  g6  h6  i6
rank 5   ───────────── 楚 河 ─────────────
rank 4   ───────────── 汉 界 ─────────────
rank 3   a3  b3  c3  d3  e3  f3  g3  h3  i3
rank 2   a2  b2  c2  d2  e2  f2  g2  h2  i2
rank 1   a1  b1  c1  d1  e1  f1  g1  h1  i1
rank 0   a0  b0  c0  d0  e0  f0  g0  h0  i0     ← 红方底线（帅 e0，a0 红方左车）
         a   b   c   d   e   f   g   h   i
```

- 文件 = 字母 `a`~`i`，行 = 数字 `0`~`9`。
- 红方在下（行 0），黑方在上（行 9）。`e0` 红帅，`e9` 黑将。
- 着法固定 4 字符：**起点 + 终点**，例如 `h2e2`（红炮二平五）、`h9g7`（黑马 8 进 7）。

### 1.3 本软件 → 引擎（下行命令）

| 命令 | 时机 | 说明 |
| --- | --- | --- |
| `uci` | 启动探测 | 期望 `uciok` |
| `ucci` | 兼容探测 | 仅在 `uci` 无响应时发送，期望 `ucciok` |
| `setoption name <名称> value <值>` | 参数变化时 | 名称与取值范围来自引擎自己上报的 `option` 行 |
| `isready` | 启动后 / 测试连接 | 期望 `readyok`；引擎首次 `isready` 通常在这里加载权重 |
| `ucinewgame` | 每局开始时 | 通知引擎清空置换表与历史启发 |
| `position startpos moves a b c` | UCI 模式 | 从初始局面 + 着法序列下发 |
| `position fen <FEN> moves a b c` | UCI（自定义局面）/ UCCI（总是） | UCCI 引擎对 `startpos` 支持不一，故统一用 FEN 形式 |
| `go depth N` | 固定深度模式 | 两种协议相同 |
| `go movetime N` | 每步限时模式（毫秒） | **仅 UCI** |
| `go time N` | 每步限时模式（毫秒） | **仅 UCCI**（UCCI 无 movetime） |
| `stop` | 用户改局面 / 超时 / 终止 | 引擎应尽快回 `bestmove` |
| `quit` | 程序退出 | 优雅关闭；2 秒未退出则强制结束进程 |

**每次局面变化都会重新下发完整局面**（`position ... moves 全部着法`），因为引擎自身不保存、也不校验历史。

### 1.4 引擎 → 本软件（上行输出）

#### `id` 行

```
id name Pikafish 2026-09-06
id author the Pikafish developers (see AUTHORS file)
```

`id name` 会作为引擎在界面上的显示名；缺失时回退为 exe 文件名。

#### `option` 行（动态参数发现的来源）

```
option name Threads type spin default 1 min 1 max 1024
option name Hash type spin default 16 min 1 max 33554432
option name Move Overhead type spin default 10 min 0 max 5000
option name SyzygyPath type string default <empty>
option name UCI_ShowWDL type check default false
option name Clear Hash type button
option name Style type combo default Normal var Solid var Normal var Risky
```

- 名称与默认值**允许含空格**（如 `Move Overhead`），本软件按关键字切分，不会解析错。
- 类型 → 界面控件映射：

| type | 界面控件 | 下发值 |
| --- | --- | --- |
| `spin` | 滑块（范围 min~max） | 整数字符串 |
| `check` | 勾选框 | `true` / `false` |
| `combo` | 下拉框（选项来自 `var`） | 选中的文本 |
| `string` | 单行输入框 | 原文本 |
| `button` | 按钮（点一下即下发） | 空字符串 |

- 本软件**不硬编码任何参数清单**：引擎暴露什么，界面就显示什么。
  已固定展示的 `Threads` / `Hash` / `MultiPV` / `SyzygyPath` 会自动从动态区跳过，避免重复。

#### `info` 行

```
info depth 18 seldepth 25 multipv 3 score cp 123 nodes 4567890 nps 1234567 time 3700 hashfull 512 pv h2e2 h9g7 c3c4
info depth 5 score mate -2 pv e0e1
info depth 1 currmove h2e2 currmovenumber 1
info string NNUE evaluation using pikafish.nnue
```

本软件解析的字段：

| 字段 | 含义 | 用途 |
| --- | --- | --- |
| `depth` | 当前搜索深度 | 状态栏与最佳着法面板 |
| `seldepth` | 选择性搜索深度 | 记录 |
| `multipv` | 这是第几条候选（1 = 最佳） | 多候选列表分组；**同序号只保留最新一条** |
| `score cp X` | 分值，单位厘兵（1 兵 = 100） | 胜率换算 |
| `score mate N` | N 步内将死（负数为被杀） | 直接 100% / 0% |
| `nodes` | 已搜索节点数 | 状态栏、对战报告的平均节点 |
| `nps` | 每秒节点数 | 状态栏、对战报告 |
| `time` | 已思考毫秒数 | 状态栏、对战报告 |
| `hashfull` | 置换表占用千分比 | 记录 |
| `pv ...` | 主变例（空格分隔的 UCI 着法） | 主变例展示、候选着法中文记谱 |

- `score` 以**走子方**为基准（UCI 约定）；界面显示的是换算后的**红方胜率**。
- `info string ...` 的内容长度不定，本软件整行丢弃，不会解析错。
- 未知字段被安全跳过，因此对各家引擎的扩展输出都具备容错性。

#### `bestmove` 行

```
bestmove h2e2 ponder h9g7
```

- 本软件只取第一个 token（`h2e2`）。
- `bestmove none` / `bestmove 0000` / 空 → 视为该方无法走子，**判该方负**。
- `bestmove` 的合法性由**本软件的规则引擎**校验（引擎不校验）：坐标不合法、或走法违反中国象棋规则 → **判该方负**并记录原因。

### 1.5 超时与异常处理

| 情况 | 本软件行为 |
| --- | --- |
| 引擎在某步思考超过硬上限 | 先发 `stop`，再等 3 秒；仍无 `bestmove` → 判定引擎无响应 |
| 硬上限取值 | 限时模式 = 标称限时 + 60 秒；深度模式 = 60 秒 + 每层 3 秒 |
| 引擎进程意外退出 | 读取 goroutine 结束 → 通过 `exited` channel 通知；提示中带上 stderr 最后 40 行 |
| 对战中一方崩溃 | 该局判该方负，**另一个引擎不受影响**，下一局尝试重启该引擎 |
| 程序退出 | 对全部引擎发 `quit`，2 秒未退出则 `Process.Kill()` |

## 二、引擎目录与文件规范

### 2.1 目录结构（推荐）

```
xiangqi-go-v1.3\
├── xiangqi.exe
├── engines\                       ← 引擎库根目录（与 exe 同目录）
│   ├── pikafish-20260906\         ← 每个引擎一个子目录
│   │   ├── Pikafish-...-avx2.exe
│   │   └── pikafish.nnue          ← 权重与 exe 同目录
│   ├── elephant-eye\
│   │   ├── elephanteye.exe
│   │   └── ...
│   └── test_engine\
│       ├── Pikafish-Windows-x86-64-universal.exe
│       └── pikafish.nnue
└── matches\                       ← 对局记录输出（自动创建）
```

- 扫描深度：`engines\` 下最多 3 层子目录。
- 同一个子目录里可以有多个 `.exe`（例如同一引擎的 avx2 / sse 两个版本），**每个都会单独探测并注册**。

### 2.2 文件规范（关键）

1. **权重与 exe 必须放在同一个文件夹**。绝大多数象棋引擎（含 Pikafish）按「exe 所在目录」查找同名/默认权重，本软件也是把引擎的工作目录（`cmd.Dir`）设为 exe 所在目录，因此：
   - `Pikafish-...-avx2.exe` 与 `pikafish.nnue` 放在同一层 → 正常加载；
   - 权重放在上一层或另一个盘 → 引擎可能启动成功但棋力异常（退化），或直接报错退出。
2. 引擎目录**不要放无关的 exe**（安装程序、GUI 前端等）：它们会被逐个数进去探测，虽然不会崩溃，但会拖慢扫描并产生「无法识别为象棋引擎」的提示。
3. 路径可以含空格与中文（例如 `D:\Engines\皮卡鱼 20260906\` 就同时含空格与中文），程序全程按原样处理，无需改名。
4. 命名建议：目录名用小写英文 + 版本号（`pikafish-20260906`），便于在长列表里一眼认出；引擎显示名取自引擎自己上报的 `id name`，与目录名无关。

### 2.3 外部引擎目录

除 `engines\` 外，还可以把**任意目录**登记为扫描目标（「添加外部引擎目录」）。登记的目录会写进 `engines.json` 的 `search_dirs`，之后每次扫描都会覆盖。适用于：

- 引擎放在 D 盘、E 盘等其它位置；
- 引擎目录里还放着作者提供的说明/权重/开局库，不想搬动；
- 想临时挂一个下载好的引擎做对比测试。

## 三、追加 / 移除引擎的完整步骤

### 3.1 追加引擎（三步法）

**第 1 步：放入引擎库**

从 GitHub Releases / 引擎官网下载压缩包，解压后把**整个引擎文件夹**复制到 `engines\` 下的一个子目录中。

```
把  Pikafish-20260906\  (解压出来的整个文件夹)
放成 engines\pikafish-20260906\
```

或者：点软件工具栏「引擎管理」→「添加外部引擎目录…」，选择引擎所在目录（可以是任意位置）。
也可以点「打开引擎库目录」让资源管理器直接打开 `engines\`。

**第 2 步：确认 exe 与权重同目录**

打开那个子目录，确认 exe 和权重文件（如 `pikafish.nnue`）在同一层。

```
engines\pikafish-20260906\
    Pikafish-Windows-x86-64-universal.exe
    pikafish.nnue                        ← 必须和 exe 在一起
```

**第 3 步：让软件识别它**

- 路径 A：点「引擎管理」→「重新扫描引擎」（立即生效，推荐）；
- 路径 B：关掉软件重开（启动时会自动扫描）。

扫描完成后：
- 能识别为象棋引擎的 → 出现在引擎列表里，显示名称、协议、路径与「可用」；
- 不能识别的 exe → 弹窗列出「无法识别为象棋引擎」的文件与原因，**不会崩溃、不会注册**。

最后在列表里点「设为己方引擎」或「设为对手引擎」即可开始使用。**全程无需改代码、无需手写配置文件。**

### 3.2 移除引擎

「引擎管理」→ 对应引擎行的「移除」→ 确认。
**只从 `engines.json` 里删掉记录，不会删除磁盘上的任何文件**（想彻底删除请自行在资源管理器里删目录）。

### 3.3 测试连接

「引擎管理」→ 对应引擎行的「测试连接」：启动该引擎、完成协议探测、发一次 `isready`，然后弹窗报告 `引擎名 / 协议 / 参数项数 / 路径`。用于在开赛前确认引擎可用。

### 3.4 设为己方 / 对手引擎

- **己方引擎**：桥接分析用的引擎（也是对战模式里「己方」那一方）。工具栏的下拉框与「引擎管理」里的按钮效果相同，选择会立即持久化到 `config.json`，并重启分析引擎。
- **对手引擎**：对战模式里对手那一方。对战面板里也有独立的下拉框。

## 四、engines.json 字段说明

位置：与 `xiangqi.exe` 同目录。首次扫描时自动创建；文件损坏时会备份为 `engines.json.bak` 并按默认重建。

```json
{
  "engines": [
    {
      "id": "eng-f250058b",
      "name": "Pikafish 2026-09-06",
      "protocol": "UCI",
      "author": "the Pikafish developers (see AUTHORS file)",
      "path": "C:\\Users\\ASUS\\Doubao\\chats\\2026-10-04\\new-chat\\皮卡鱼 20260906\\Pikafish-Windows-x86-64-universal.exe",
      "dir": "C:\\Users\\ASUS\\Doubao\\chats\\2026-10-04\\new-chat\\皮卡鱼 20260906",
      "source": "preset",
      "options_cached": [
        { "name": "Threads", "type": "spin", "default": "1", "min": 1, "max": 1024 },
        { "name": "Hash", "type": "spin", "default": "16", "min": 1, "max": 33554432 },
        { "name": "MultiPV", "type": "spin", "default": "1", "min": 1, "max": 128 }
      ]
    }
  ],
  "default_engine": "eng-f250058b",
  "search_dirs": [
    "D:\\engines\\elephant-eye"
  ],
  "updated_at": "2026-02-14 21:30:05"
}
```

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `engines` | 数组 | 全部已注册引擎 |
| `engines[].id` | 字符串 | **稳定唯一 id**，由 exe 路径的 FNV-32 哈希生成（形如 `eng-1a2b3c4d`）。移动/改名后 id 会变，需要在界面重选 |
| `engines[].name` | 字符串 | 引擎自报名称（`id name`）；未上报时回退为 exe 文件名 |
| `engines[].protocol` | 字符串 | `"UCI"` 或 `"UCCI"` |
| `engines[].author` | 字符串 | 引擎自报作者（`id author`），可选 |
| `engines[].path` | 字符串 | exe 绝对路径 |
| `engines[].dir` | 字符串 | 引擎工作目录（= exe 所在目录），启动时作为子进程 cwd |
| `engines[].source` | 字符串 | `preset` = 预置皮卡鱼；`library` = 来自 `engines\`；`external` = 来自外部目录 |
| `engines[].options_cached` | 数组 | 上次探测缓存到的参数列表（名称/类型/默认值/min/max/枚举项），供离线展示与参数记忆 |
| `default_engine` | 字符串 | 默认己方引擎 id。首次运行自动指向预置皮卡鱼 |
| `search_dirs` | 字符串数组 | 额外扫描的外部引擎目录（「添加外部引擎目录」写入） |
| `updated_at` | 字符串 | 最后写入时间 |

> 说明：`engines[].id` 只用于界面选择与 `config.json` 的 `self_engine` / `opponent_engine` 引用；
> 引擎的**显示名**始终来自引擎自己上报的 `id name`，改 `engines.json` 里的 `name` 字段没有意义（下次扫描会被覆盖）。

### 4.1 手工编辑是否可行？

可以，但不是推荐路径：手工加一条记录后仍需引擎能被启动。**推荐永远走图形界面的「重新扫描引擎」**，让软件自己填写这些字段，避免路径转义（Windows 路径中的 `\` 在 JSON 里要写成 `\\`）出错。

## 五、常见问题排查

### 5.1 引擎能启动，但棋力明显不对（权重未加载）

**症状**：能正常出着，但深度上不去、着法很弱，或 `nps` 异常低；`info string` 里出现 `NNUE evaluation using ...` 之外的内容。

**排查步骤**

1. 打开引擎所在目录，确认权重文件（Pikafish 为 `pikafish.nnue`，约 50MB）**与 exe 在同一层**。
2. 在「引擎管理」里点「测试连接」，看参数列表里是否有 `EvalFile`。有的话，它的默认值就是引擎要找的权重文件名（Pikafish 默认 `pikafish.nnue`）。
3. 若权重文件名与默认值不一致：把它改名成 `EvalFile` 的默认值，或在参数面板「引擎动态参数」里把 `EvalFile` 改成实际文件名（改完立即 `setoption` 下发）。
4. 确认权重文件没被下载工具截断（对比压缩包内的大小）。

> 本软件把子进程的工作目录设为 **exe 所在目录**，这正是为了让引擎能按相对路径找到权重。
> 因此**不要把 exe 单独复制出来**，也不要把权重留在上一层目录。

### 5.2 引擎无法启动（缺少 VC 运行库）

**症状**：`引擎进程异常结束: exit status 0xc0000135`（或 `0xc000007b`），或弹窗「启动引擎失败」。

| 错误码 | 含义 | 处理 |
| --- | --- | --- |
| `0xc0000135` | 缺少 DLL（常见为 MSVCP140.dll / VCRUNTIME140.dll） | 安装 **Microsoft Visual C++ Redistributable 2015-2022 (x64)**；部分引擎需要 2013 版，一并装上 |
| `0xc000007b` | 32/64 位不匹配，或 DLL 位数不对 | 换用 64 位引擎（见 5.3） |
| `0xc000001d` | 非法指令（CPU 不支持该指令集） | 换用更低指令集版本（见 5.3） |
| `0xc0000142` | DLL 初始化失败 | 常见于混放了不同版本的运行库，重装 VC++ 运行库 |

引擎的 stderr 最后若干行会显示在错误提示里，可据此定位。

### 5.3 32/64 位与 CPU 指令集版本选择

中国象棋引擎通常会为同一版本发布多个可执行文件，命名类似：

```
Pikafish-avx512.exe     ← 需要 AVX-512（Intel Xeon / 部分 i9；AMD Zen4 起支持）
Pikafish-avx2.exe       ← 需要 AVX2（2013 年后的主流 CPU，推荐起点）
Pikafish-bmi2.exe       ← 需要 BMI2
Pikafish-sse41-popcnt.exe
Pikafish-x86-64.exe     ← 最保守的 64 位版本
Pikafish-x86-64-universal.exe  ← 运行时自动选择（本机预置的即为此版本）
Pikafish-32bit.exe / windows-x86  ← 32 位，除非系统是 32 位否则不要用
```

选择原则：

1. **先确认系统是 64 位**（本机 Windows 11 为 64 位）→ 只考虑 64 位版本。
2. 优先用 **universal / 自动选择** 版本（本机预置的 `Pikafish-Windows-x86-64-universal.exe` 就是这种，无需操心指令集）。
3. 没有 universal 版本时：
   - 本机 CPU 为 **AMD Ryzen 7 8845H（Zen 4）**，支持 AVX2 与 AVX-512；
   - 但从 **avx2** 版本开始试最稳妥（AVX-512 版本在部分平台上因降频反而更慢）；
   - 若启动报 `0xc000001d`，逐级降到 `sse41-popcnt` → `x86-64`。
4. 想对比指令集收益：把两个版本分别放进 `engines\` 的两个子目录，扫描后各自设为一方的引擎，跑一场自动对战，看报告里的「平均节点/秒」。

### 5.4 引擎闪退排查步骤

按顺序做，每步都能缩小范围：

1. **看错误提示**：本软件会把引擎 stderr 的最后 40 行放进错误信息。`0xc0000135` → 缺运行库（5.2）；`0xc000001d` → 指令集不兼容（5.3）。
2. **删掉多余文件**：把引擎目录里除了 exe 与权重之外的文件（GUI、安装包、其它引擎）挪走，排除加载冲突。
3. **手动跑一次**：在该目录打开 PowerShell，执行 `.\引擎.exe`。正常情况控制台会等你输入命令；输入 `uci` 回车，应看到 `id name ...` 与 `uciok`。直接闪退即为引擎自身/环境问题，与本软件无关。
4. **检查杀毒/安全软件**：部分安全软件会拦截未知 exe 启动子进程，把它加入白名单。
5. **检查路径权限**：不要放在需要管理员权限的目录（如 `C:\Program Files` 根下自建目录），换到用户目录下再试。
6. **换一个版本**：同目录放 avx2 与 sse 两个版本，各自「测试连接」，能通的那个就是兼容版本。
7. **在「引擎管理」里点「测试连接」**：如果测试连接通过但对战时失败，问题多半在时间控制（把每步限时调大，例如 1 秒以上）而不是引擎本身。

### 5.5 其他现象

| 现象 | 原因与处理 |
| --- | --- |
| 扫描结果里有「无法识别为象棋引擎」的条目 | 该 exe 不是象棋引擎（或缺少运行库无法启动）。属正常提示，不影响其它引擎 |
| 引擎列表里同一个引擎出现两次 | 同一 exe 被放在两个位置（例如 `engines\` 与外部目录各一份）。删掉一份并「重新扫描引擎」 |
| 选了的引擎变成「文件已丢失」 | exe 被移动/删除。把文件放回原路径，或重新扫描后重选 |
| UCCI 引擎思考时间异常长 | UCCI 没有 `movetime`，本软件用 `go time N` 下发；个别引擎对 `go time` 的理解是「本局剩余总时间」，此时请改用「固定深度」模式 |
| 对战中途一方反复判负 | 该引擎在本局面下返回了非法着法，或思考超时。把每步限时调大，或换用该引擎更稳的指令集版本 |

### 6.1 性能数字的口径（R9 修复）

> **为什么单独写这一节**：v1.3.0 的本文档只写了一句「3 秒搜索 ~514 万节点（~171 万 nps）」，
> 没有标注线程数、Hash、MultiPV 与硬件，读者很容易把它当成「满配性能」，
> 与实测的 16 线程满配数字相差约 5.4 倍，从而误判引擎强弱。
> **本节所有数字都必须带口径**；以后新增数字时请照此格式补齐线程 / Hash / MultiPV / 硬件 / 时间控制五要素。

**测试硬件（本机，固定不变）**

| 项目 | 值 |
| --- | --- |
| CPU | AMD Ryzen 7 8845H（8 物理核 / 16 逻辑处理器） |
| 内存 | 32 GB |
| 显示器 | 1920×1080 @ 125%（Fyne content scale = 1.3） |
| 引擎 | `Pikafish-Windows-x86-64-universal.exe`（2026-09-06）+ 同目录 `pikafish.nnue` |

**实测 nps 对照表**

| 场景 | 线程 | Hash | MultiPV | 时间控制 | 实测 nps | 口径来源 |
| --- | --- | --- | --- | --- | --- | --- |
| 单引擎 / 单 PV / 单线程 | 1 | 默认 | 1 | `go movetime 3000` | **约 171 万** | v1.3.0 测试脚本单独跑单线程探测时的读数（旧文档那个数字的真实口径） |
| 单引擎 / 多 PV / 满配 | 16 | 4096 MB | 8 | `go movetime 3000` | **约 850~950 万**（本机多次读到 8,542,628 / 8,875,493 / 9,482,550 nps） | v1.3.1 真机验证：主界面状态栏「速度 … nps」的实时读数 |
| 对战 / 双方各占满全部核 | 16 + 16 | 4096 + 1024 MB | 各 1 | 每步 300 ms | 每方约 **181 万**，双方合计约 362 万（约为单引擎峰值的 **39%**） | v1.3.0 测试报告；这正是 R5「线程超订」问题的实测证据 |
| 对战 / v1.3.1 新默认（平均分配） | 8 + 8 | 4096 + 1024 MB | 各 1 | 每步 300 ms | 未在本轮做长时间对战测量，**不做无依据的宣称** | — |

**结论（写给使用者）**

- nps 对**线程数**极其敏感，对 **MultiPV** 也敏感：MultiPV=8 时引擎要同时维护 8 条主变例，同样时间内节点数会明显低于单 PV。
- 「171 万」是**单线程**口径，不代表满配性能；满配（16 线程）约 850~950 万。
- 两个引擎同时对战时，**双方线程之和不要超过逻辑处理器数**（本机 16）。
  v1.3.0 的默认值是双方各 16（合计 32，超订 2 倍），实测每方只剩约 181 万，
  合起来反而只有单引擎峰值的 39%——线程越多越慢。
  v1.3.1 已把默认值改为**双方平摊**（各 `NumCPU/2`），并在「引擎对战」页
  增加超订警告与「按核心数自动平均分配」按钮（见 README 的 R5 条目）。
- 想要复现上表数字：`go movetime 3000` + `setoption name MultiPV value 8` +
  `setoption name Threads value 16` + `setoption name Hash value 4096`，
  读数取自主界面状态栏的「速度 … nps」。

## 七、验证钩子（可选，供脚本化测试）

正常双击运行不会触发任何钩子。仅在设置了对应环境变量时才生效，用于复现验证：

| 环境变量 | 作用 |
| --- | --- |
| `XQ_MOVES="h2e2 h9g7"` | 启动后应用一段 UCI 着法序列（等价于在「粘贴输入」里粘贴） |
| `XQ_MODE=bridge\|match` | 启动后切换到指定模式 |
| `XQ_TAB=0\|1\|2` | 启动后切到「参数设置 / 着法列表 / 粘贴输入」页签 |
| `XQ_SHOW_ENGINES=1` | 启动后打开「引擎管理」窗口 |
| `XQ_RESCAN=1` | 启动后自动执行一次「重新扫描引擎」 |
| `XQ_AUTOMATCH=3` | 启动后自动开始 3 局对战（用当前引擎与时间控制设置） |
| `XQ_STRESS=50` | 启动后连续 50 次「粘贴着法序列 + 复制最佳着法」，并把耗时打到 stderr 与状态栏 |
| `XQ_SHOT=path.png` | 延迟若干秒后把界面自身渲染结果存为 PNG |
| `XQ_SHOT_WINDOW=main\|engines` | 截图目标窗口（默认 main） |
| `XQ_SHOT_DELAY=8` | 截图延迟秒数（默认 8） |
| `XQ_QUIT=5` | 截图 / 对战结束后再等 N 秒自动退出 |
| `XQ_DEBUG=1` | 打印 DPI 与窗口尺寸校正日志、布局尺寸 |

示例（PowerShell）：

```powershell
$env:XQ_MOVES='h2e2 h9g7 c3c4'; $env:XQ_SHOT='D:\shot.png'; $env:XQ_SHOT_DELAY='12'; $env:XQ_QUIT='2'
.\xiangqi.exe
# 12 秒后 D:\shot.png 即为界面自身的物理像素截图，2 秒后程序自动退出
```

## 八、从 GitHub 下一个引擎到能用：完整步骤（v1.5 新增）

这一节是**给使用者**的：你在 GitHub 上找到一个中国象棋引擎，怎么把它接进本软件。
每一步都给出「放哪里、点哪里、看到什么才算成功」。

### 8.1 先确认它是不是「引擎」（不是 GUI 程序）

中国象棋引擎在 GitHub 上通常长这样：

| 你会看到 | 是不是引擎 | 说明 |
| --- | --- | --- |
| 一个 `.exe`，双击后是**黑窗口**，你打字它才回应 | ✅ 是引擎 | 典型 UCI/UCCI 引擎 |
| 一个带棋盘界面的程序 | ❌ 不是 | 那是 GUI（如 象棋巫师 / WinBoard），本软件不需要 |
| `.exe` 旁边有 `.nnue` / `.bin` 大文件（几十 MB） | ✅ 是引擎 | 那是神经网络权重，**必须和 exe 放同一个目录** |
| 只有源码 `.cpp`，让你自己编译 | ⚠️ | 需要你自己编译出 exe 再来接 |

**判断最快的方法**：双击 exe，在黑窗口里敲一行 `uci` 回车。
如果它回了一堆 `id name ...` / `option name ...` / 最后一行 `uciok` → 它就是 UCI 引擎；
如果回 `ucciok` → 是 UCCI 引擎。两种本软件都支持，**不用你告诉它用哪种**。

### 8.2 放文件：位置只有一个规则

把**整个引擎文件夹**（exe + 权重 + 它自带的 dll）一起放进本软件的引擎库目录：

```
<软件所在目录>\engines\<你自己起的名字>\
```

例如：

```
<软件所在目录>\engines\Pikafish-2026-09\
    Pikafish-Windows-x86-64-universal.exe
    pikafish.nnue
```

要点：

- **exe 和权重必须在同一个目录**。引擎默认按「exe 所在目录 / 权重文件名」去找权重，分开放就会报权重加载失败。
- **别改 exe 的文件名**（有些引擎会把文件名写进日志或自检）。
- **别把 exe 单独复制出来**：很多引擎依赖同目录的 dll，单独一个 exe 会启动即崩。
- 子目录可以有，本软件会往下扫最多 3 层。

### 8.3 注册：点一下「重新扫描引擎」

1. 打开本软件 → 工具栏 **「引擎管理」**
2. 点 **「重新扫描引擎」**（也可以先点「打开引擎库目录」确认文件放对了）
3. 扫描会**真的启动每个 exe 并用 UCI/UCCI 探测协议**，所以会花几秒到十几秒
4. 出现你的引擎名字，右边显示绿色 **「可用」** → 成功

如果显示 **「文件已丢失」**：文件被你移动/改名了，放回去再扫一次。
如果显示 **「无法识别为象棋引擎」**：看下面 8.5 的排查表。

> 「可用 / 文件已丢失」是**每次刷新都用 `os.Stat` 现场校验**的，不是读缓存字段。
> 所以你把 exe 改名，列表立刻会红；改回来再刷新就恢复绿。可以自己试一下。

### 8.4 用起来：三种玩法

| 想做什么 | 怎么点 |
| --- | --- |
| 用这个引擎分析局面 | 工具栏「己方引擎」下拉选中它 → 点棋盘走子 / 粘贴着法，右侧自动出最佳着法 |
| 让这个引擎和另一个引擎对战 | 切到 **「引擎对战」** → 上面选己方引擎、下面选对手引擎 → 点「开始对战」 |
| **同一个引擎自我对弈**（自己跟自己下，测稳定性/看开局库） | 己方和对手**选同一个引擎**即可。软件会启动**两个独立进程**，互不影响；日志里「己方 / 对手」就代表这两台进程 |

**双方参数可以分开设**：「引擎对战」页里，
- 「时间控制方式」是双方共用的（每步限时 / 每局总时间 / 固定深度 三选一）
- 「己方思考参数」和「对手思考参数」各自有 每步限时 / 每局总时间 / 固定深度 三个滑块
- 想让对手更强：把对手的「每步限时」调大；想让己方慢棋快点：调小自己的
- 对手那三个滑块默认跟随己方；**拖动任意一个就表示对手单独用这一档**

对战线程也建议检查一下：滑块下方会给出超订警告，
点「按核心数自动平均分配」是最稳的（本机 8 核 16 线程 → 双方各 8）。

### 8.5 出问题怎么查

| 现象 | 原因与处理 |
| --- | --- |
| 扫描报「无法识别为象棋引擎」 | ① 不是象棋引擎（比如是国际象棋引擎）；② 缺 VC++ 运行库，装 [Microsoft Visual C++ Redistributable](https://aka.ms/vs/17/release/vc_redist.x64.exe)；③ 下载的是 ARM 版而本机是 x64（或反过来）；④ 被杀毒软件拦了，把引擎目录加白名单 |
| 双击 exe 黑窗口一闪就没 | 同上 ②③；也可能是缺同目录的 dll |
| 能用但棋力很弱 / 深度上不去 | 权重没加载。看引擎输出里有没有 `NNUE evaluation using ...`；确认 `.nnue` 与 exe 同目录、文件名没被改 |
| 选了引擎但右侧一直「等待引擎输出」 | 「引擎管理 → 测试连接」看具体报错；再看「参数设置 → 线程」是不是被设成了 0 |
| 对战中途一方反复判负 | 该引擎返回了非法着法或思考超时。把「每步限时」调大，或换该引擎更稳的版本 |
| 想临时让引擎完全停下来（测试界面、省电） | 工具栏 **「关闭引擎」**；已分析过的局面仍然能看（缓存回放），点「启动引擎」恢复 |

### 8.6 接一个 UCCI 引擎（旋风 / 名手 / 象眼等）

不用做任何额外配置。本软件先发 `uci`，3 秒内没响应就自动改发 `ucci`；
收到 `ucciok` 即判定为 UCCI，之后：
- 思考用 `go time <毫秒>`（UCCI 没有 `movetime`）
- 局面统一用 `position fen <FEN> moves ...` 下发（UCCI 对 `startpos` 支持不一）

个别 UCCI 引擎把 `go time` 理解成「本局剩余总时间」，
遇到思考时间异常长的情况，改把「时间控制方式」切到 **「固定深度」** 即可。

### 8.7 一份能跑的 engines.json 长什么样

放在软件目录下的 `engines.json`，本软件会自动维护，你一般不用手改。
结构如下（`options_cached` 是扫描时探测到的参数，删掉也能跑）：

```json
{
  "engines": [
    {
      "id": "eng-f250058b",
      "name": "Pikafish 2026-09-06",
      "protocol": "UCI",
      "author": "the Pikafish developers",
      "path": "<软件目录>\\engines\\Pikafish-2026-09\\Pikafish-Windows-x86-64-universal.exe",
      "dir":  "<软件目录>\\engines\\Pikafish-2026-09",
      "source": "library",
      "options_cached": []
    }
  ],
  "default_engine": "eng-f250058b",
  "search_dirs": null,
  "updated_at": "2026-10-08 12:00:00"
}
```

- `id` 由 exe 路径哈希得到，**移动文件会导致 id 变化**（这是有意的：路径就是身份）。
- `source`：`preset` = 预置皮卡鱼；`library` = 引擎库目录扫到的；`external` = 手动添加的外部目录。
- **没有** `executable` 之类的「是否可用」字段——可用性是运行时 `os.Stat` 现场判定的，不落盘。
